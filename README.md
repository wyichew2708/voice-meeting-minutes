# voice-meeting-minutes

A browser app that records a meeting live, transcribes it in real time, works out who is
speaking, asks you to name the voices it does not recognise, and writes the minutes when the
meeting ends.

**Status: design draft. No code yet.**

- **[docs/solution-design.md](docs/solution-design.md)** — architecture, models, speaker
  identification, minutes generation, deployment, risks, delivery plan
- **[docs/api-contract.md](docs/api-contract.md)** — WebSocket protocol, REST surface,
  database schema, upstream service contracts, configuration

## What it does

| | |
|---|---|
| **Record** | Start / Pause / End. Nothing else to configure. |
| **Transcribe live** | Zoom/Teams-style: a grey interim line that settles into a final one ~1.2 s after each person stops talking. |
| **Identify speakers** | Voices are clustered live and matched against a voiceprint library, so people who have been in a previous meeting are named automatically. |
| **Ask when unsure** | A new voice gets a non-blocking card — *"Who is Speaker 2?"* — with a playable clip and suggestions. Or double-click any speaker label to rename it; the change applies to every line that person has already said. |
| **Write the minutes** | Summary, topics, decisions, action items with owners and due dates, open questions. Every line links back to the moment in the transcript and the audio. |

## Where it runs

Inference is on the RHEL GPU box that already serves
[`voicebot`](https://github.com/wyichew2708/voicebot). **The speech recognition is not a new
deployment** — it is voicebot's MERaLiON-on-vLLM endpoint
(`/v1/audio/transcriptions`, port 8801) reused unchanged, and the minutes are generated by the
Qwen3.6 instance already running on port 8000. That single ASR carries the live interim text as
well as the final transcript, so the only new GPU cost is a ~1.5 GB speaker sidecar (ECAPA
embeddings + pyannote); the gateway is CPU-only.

Sharing one recogniser with live voicebot calls is the one thing that needed real design rather
than a config line. Interim transcription runs under a governor that keeps a single request in
flight, drops late partials instead of queueing them, backs off when the endpoint slows, and
suspends entirely while `on_call` is true — the signal voicebot already publishes so its own
warm-up can stand aside. Final lines are never governed. See
[§3.3](docs/solution-design.md#33-sharing-one-asr-endpoint-with-live-voicebot-calls).

The audio gates that stop the recogniser inventing sentences over silence, the browser mic
capture, and the ASR client are all lifted from voicebot rather than rewritten —
see [the reuse table](docs/solution-design.md#what-is-lifted-from-voicebot-and-how).

## Before implementation starts

Five things need answers — pyannote model gating, languages, tenancy, meeting-room mic setup,
and retention defaults. They are listed with context in
[§12 of the design](docs/solution-design.md#12-decisions-needed-before-implementation).
The sixth — whether to stand up a second ASR replica — is **settled: no.** One shared
endpoint, governed.
